# Udozo POS for Windows

A Tauri 2 shell around pos.udozo.com, published only through the Microsoft Store as an MSIX package (`docs/UDOZO_POS_PLAN.md`, milestone 1).

- **What it does now:** one window, maximised, opening the bundled start page (`start/`), which waits for the internet and then opens `https://pos.udozo.com/app`. Only pos.udozo.com and udozo.com stay in the window. Every other address opens in the browser. One copy runs at a time; starting a second copy brings the first one forward. Pages get no access to the app's commands (no capabilities). The bundled till screens, offline selling, printing and the cash drawer come with milestone 9.
- **Windows 10 (1809) or later**, on WebView2, which Windows 11 includes and Windows 10 gets with Edge.
- **Icons and Store tiles** are generated by `python scripts/brand-assets.py`. Never edit them by hand.

## Building

Rust is not needed on your own machine: `.github/workflows/pos-windows.yml` builds on `windows-latest` on every push to `main` touching this folder, or when run by hand (Actions > Udozo POS for Windows > Run workflow):

1. checks the settings (`npm test -w @udozo/pos-windows`);
2. builds `udozo-pos.exe` (`npx @tauri-apps/cli@2 build`; Tauri's own installers are switched off);
3. lays out the package (`scripts/msix-layout.mjs`: the executable, `msix/Assets` and `msix/AppxManifest.xml` with its values filled in);
4. packs it with the Windows SDK's `makeappx`;
5. keeps `udozo-pos.msix` (and the build's `Cargo.lock`) as the run's artifact `udozo-pos-msix`.

With Rust and the Windows SDK installed you can do the same yourself: `npm run tauri -w @udozo/pos-windows -- build`, then `npm run msix:layout -w @udozo/pos-windows`, then `makeappx pack /d msix-layout /p udozo-pos.msix`.

## Releasing in the Microsoft Store

1. In Partner Center (a free company developer account in Udozo's name), reserve the name **Udozo POS**.
2. Copy the app's **Product identity** (Package/Identity/Name, Package/Identity/Publisher and Package/Properties/PublisherDisplayName) into the repository variables `POS_MSIX_IDENTITY_NAME`, `POS_MSIX_PUBLISHER` and `POS_MSIX_PUBLISHER_NAME` (Settings > Secrets and variables > Actions > Variables). Without them the package carries a test identity, which the Store refuses.
3. Raise `version` in `src-tauri/tauri.conf.json` and `Cargo.toml` (every submission needs a higher one; the package's version is it with a fourth part of 0), push, and download the run's `udozo-pos-msix`.
4. Upload `udozo-pos.msix` to the submission unsigned: the Store signs it. The `runFullTrust` capability is declared, and needs the short justification Partner Center asks for: a desktop app with printers and a cash drawer.
5. Once the Store has published it, an admin sets the listing's address (`https://apps.microsoft.com/detail/<product id>`) on admin.udozo.com > POS > App links. pos.udozo.com's Windows button then opens it.

## Known limits for now

- Sign-in with Google or Facebook on udozo.com opens in the browser, not the window. Sign in with email and password, or with WhatsApp.
- Pages opened in a new tab from inside the window (`target="_blank"`) follow WebView2's own behaviour.
